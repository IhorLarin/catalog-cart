## Крок 0 — Інфраструктура + типи

**Зроблено.** Vite + React 19 + TS, Tailwind 4 через `@tailwindcss/vite`, структура папок,
документація (README, ADR, api, design-system), доменні типи `Product` / `ProductsResponse`.

### Граблі

**Git-індекс накопичувальний.** Два `git add` підряд не створюють два коміти — файли
складаються в одну купу, і перший `git commit` забирає її цілком. Другий коміт сказав
`nothing to commit`, бо додавати вже нічого не залишилось. Меседж не впливає на те, що
потрапить у коміт.
→ Порядок завжди: `add` → **`status`** → `commit`.

**Git не зберігає порожні папки.** Він відслідковує файли, не директорії. Сім створених
папок у коміт не потрапили. Обхід — `.gitkeep`, але свідомо не робили: файл-заглушка,
який існує тільки щоб обійти обмеження, стає сміттям. Папки заповнились реальними файлами
за два кроки.

**`brand: string` — тип, що бреше компілятору.** У DummyJSON поля `brand` немає в частині
категорій (`groceries`). З типом `string` TypeScript пропустив би `product.brand.toUpperCase()`
без попередження, а в рантаймі це падіння. Правильно — `brand?: string`.
Тип, який дозволяє написати падаючий код, гірший за відсутність типу.

**Версії перевіряти по registry, не по памʼяті.** За останній рік мажори: Vite 8,
React Router 8, Tailwind 4. `react-router` вимагає Node 22.22+ (`engines`), пакета
`react-router-dom` більше не існує. Шаблон `react-ts`, а не `react-compiler-ts` —
React Compiler автоматично мемоізує і приховав би ре-рендери, на яких вчимо селектори.

**Корисне.** `git check-ignore -v .idea` — показує файл і номер рядка правила, яке ігнорує шлях.

## Крок 0.5 — Дизайн-система, Layout, Router, `/styleguide`

**Зроблено.** Токени під референс-макет (кораловий акцент, сірий шелл, Oswald + Inter +
Geist Mono), `Layout` з шапкою і `Outlet`, 5 маршрутів, сторінка `/styleguide`.

### Граблі

**`return AppRouter` замість `return <AppRouter />`.** Головний урок кроку.
Код **валідний** для TypeScript: повернути функцію з функції — легальна операція, типи
збігаються. Але **невалідний** для React: він отримав функцію замість JSX і впав у рантаймі
з `Functions are not valid as a React child`.

Дві різні системи правил, накладені одна на одну:
- TS перевіряє типи **до** запуску → пропустив
- React перевіряє результат рендеру **під час** виконання → впав

ESLint теж мовчав: у Vite-шаблоні немає `eslint-plugin-react`, а базові правила такий
патерн не ловлять.

**Наслідок — конвенція проєкту.** Кожен компонент отримує явний `: ReactNode`. Тоді
TypeScript звіряє повернене значення з тим, що React вміє рендерити, і підсвічує помилку
в редакторі. Без явного типу він виводиться неявно, і помилка проходить.

**`@theme` — це не `:root`.** `:root` створює CSS-змінну, і все. `@theme` створює змінну
**плюс** генерує з неї утиліти. Без токена `--color-page` класу `bg-page` не існує — і при
цьому в консолі не буде жодної помилки, клас просто не застосується.

**Назва токена — це API.** Неймспейс визначає, які класи зʼявляться: `--color-*` → `bg-`/`text-`/
`border-`, `--radius-*` → `rounded-`, `--tracking-*` → `tracking-`. Тому токен називається
`--color-page`, а не `--page-bg` — інакше `bg-page` не згенерується. А `--opacity-disabled`
класу не дасть взагалі: цей неймспейс утиліт не генерує.

**Vite не завжди підхоплює новий файл.** Створений при запущеному `pnpm dev` `StyleguidePage`
відрендерився без стилів. Лікується перезапуском dev-сервера.

**Що видно на styleguide.** Рядок `font-display text-sm uppercase tracking-caps` повторюється
в кнопках чотири рази, у бейджах тричі. Коли всі варіанти лежать один під одним, дублювання
лізе в очі — це і є місток до `<Button>` та Storybook у Проєкті 7.

## Відкриті питання

- **ADR-007** — фільтр по ціні: сервер чи клієнт. Вирішуємо на Кроці 4, дописуємо в ADR самі.
- **ESLint** — додати `eslint-plugin-react` (ловив би `return AppRouter`) і `import/order`
  (сортування імпортів замість ручних коментарів-груп). Зробити, коли зʼявиться кодова база.
- **Скоуп vs API** — свотчі кольорів і чіпи розмірів з референсу нічим наповнити: у DummyJSON
  таких полів немає. На їх позиції — рейтинг і наявність.
