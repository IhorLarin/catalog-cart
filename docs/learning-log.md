# Лог навчання

Хронологія проєкту: що зроблено на кроці, які граблі знайдені руками.
Теорія по темах — у `react-cheatsheet.md`. Обґрунтування рішень — у `docs/adr.md`.

## Крок 0 — Інфраструктура + типи

**Зроблено.** Vite + React 19 + TS, Tailwind 4 через `@tailwindcss/vite`, структура папок,
документація (README, ADR, api, design-system), доменні типи `Product` / `ProductsResponse`.

### Граблі

**Git-індекс накопичувальний.** Два `git add` підряд не створюють два коміти — файли
складаються в одну купу, і перший `git commit` забирає її цілком. Другий коміт сказав
`nothing to commit`, бо додавати вже нічого не залишилось. Меседж не впливає на те, що
потрапить у коміт.
→ Порядок завжди: `add` → **`status`** → `commit`.

**Git не зберігає порожні папки.** Він відслідковує файли, не директорії. Сім створених
папок у коміт не потрапили. Обхід — `.gitkeep`, але свідомо не робили: файл-заглушка,
який існує тільки щоб обійти обмеження, стає сміттям. Папки заповнились реальними файлами
за два кроки.

**`brand: string` — тип, що бреше компілятору.** У DummyJSON поля `brand` немає в частині
категорій (`groceries`). З типом `string` TypeScript пропустив би `product.brand.toUpperCase()`
без попередження, а в рантаймі це падіння. Правильно — `brand?: string`.
Тип, який дозволяє написати падаючий код, гірший за відсутність типу.

**Версії перевіряти по registry, не по памʼяті.** За останній рік мажори: Vite 8,
React Router 8, Tailwind 4. `react-router` вимагає Node 22.22+ (`engines`), пакета
`react-router-dom` більше не існує. Шаблон `react-ts`, а не `react-compiler-ts` —
React Compiler автоматично мемоізує і приховав би ре-рендери, на яких вчимо селектори.

**Корисне.** `git check-ignore -v .idea` — показує файл і номер рядка правила, яке ігнорує шлях.

## Крок 0.5 — Дизайн-система, Layout, Router, `/styleguide`

**Зроблено.** Токени під референс-макет (кораловий акцент, сірий шелл, Oswald + Inter +
Geist Mono), `Layout` з шапкою і `Outlet`, 5 маршрутів, сторінка `/styleguide`.

### Граблі

**`return AppRouter` замість `return <AppRouter />`.** Головний урок кроку.
Код **валідний** для TypeScript: повернути функцію з функції — легальна операція, типи
збігаються. Але **невалідний** для React: він отримав функцію замість JSX і впав у рантаймі
з `Functions are not valid as a React child`.

Дві різні системи правил, накладені одна на одну:
- TS перевіряє типи **до** запуску → пропустив
- React перевіряє результат рендеру **під час** виконання → впав

ESLint теж мовчав: у Vite-шаблоні немає `eslint-plugin-react`, а базові правила такий
патерн не ловлять.

**Наслідок — конвенція проєкту.** Кожен компонент отримує явний `: ReactNode`. Тоді
TypeScript звіряє повернене значення з тим, що React вміє рендерити, і підсвічує помилку
в редакторі. Без явного типу він виводиться неявно, і помилка проходить.

**`@theme` — це не `:root`.** `:root` створює CSS-змінну, і все. `@theme` створює змінну
**плюс** генерує з неї утиліти. Без токена `--color-page` класу `bg-page` не існує — і при
цьому в консолі не буде жодної помилки, клас просто не застосується.

**Назва токена — це API.** Неймспейс визначає, які класи зʼявляться: `--color-*` → `bg-`/`text-`/
`border-`, `--radius-*` → `rounded-`, `--tracking-*` → `tracking-`. Тому токен називається
`--color-page`, а не `--page-bg` — інакше `bg-page` не згенерується. А `--opacity-disabled`
класу не дасть взагалі: цей неймспейс утиліт не генерує.

**Vite не завжди підхоплює новий файл.** Створений при запущеному `pnpm dev` `StyleguidePage`
відрендерився без стилів. Лікується перезапуском dev-сервера.

**Що видно на styleguide.** Рядок `font-display text-sm uppercase tracking-caps` повторюється
в кнопках чотири рази, у бейджах тричі. Коли всі варіанти лежать один під одним, дублювання
лізе в очі — це і є місток до `<Button>` та Storybook у Проєкті 7.

## Крок 1 — Каталог на `useState`

**Зроблено.** `api/products.ts` (fetch + перевірка `response.ok`), `FetchState<T>` через
discriminated union, `AbortController` у `useEffect`, `ProductCard` + сітка, утиліти ціни в `lib/`.
Zustand навмисно не використовували — щоб на Кроці 2 відчути різницю на власному коді.

### Граблі

**Компонент не може бути `async`.** Написав `export async function CatalogPage()` — React
отримав Promise замість JSX, не зміг його відрендерити, рендерив знову, і кожен рендер робив
новий HTTP-запит. Кілька сотень запитів за секунди → DummyJSON відповів `429 Too Many Requests`,
а заблокована відповідь не має CORS-заголовків, звідси друга помилка в консолі про CORS.
→ Рендер мусить бути чистим. Запит — побічний ефект, його місце в `useEffect`.

**`useEffect` теж не може бути `async`.** Він мусить повернути функцію очищення або нічого,
а `async` завжди повертає Promise. Тому async-логіка живе у внутрішній функції:
```tsx
useEffect(() => {
  async function loadProducts() { ... }
  void loadProducts()
}, [])
```
І це не забаганка React: **функції очищення мусять бути синхронними**, щоб виконатись рівно
перед наступним запуском ефекту. Якби React приймав `async`, очищення відкладалось би — і
`AbortController` в ньому не працював би взагалі.

**Прибрав `async`, залишив `Promise<ReactNode>`.** Тип повернення не оновив → TypeScript
підсвітив помилку в редакторі. Саме те, для чого ми ввели правило явного `: ReactNode`
на Кроці 0.5 — раніше та сама помилка ловилась тільки в рантаймі.

**Три `useState` замість одного стану.** 2×2×2 = 8 комбінацій, осмислених 3. Щоб безглузді
(`loading: true` + `error` одночасно) не виникали, треба **памʼятати** скидати руками
(`setError(null)` перед новим запитом). Забув один рядок — UI показує неправду, компілятор
мовчить. Discriminated union робить ці комбінації такими, що їх не скомпілюєш.

**`error: Error` замість `message: string`** — свідомий вибір. У `docs/api.md` записано, що
404 і 5xx мусять давати різні екрани. З рядком інформація втрачена безповоротно; з обʼєктом
залишається `name`, `stack`, і можна зробити `class ApiError extends Error { status: number }`.

**У `catch` змінна має тип `unknown`.** Кинути в JS можна будь-що (`throw "рядок"` валідний),
тому доступ до `.message` без звуження TypeScript не дає:
`error instanceof Error ? error : new Error("Unknown error")`.

**Скасований запит виглядає як помилка.** Після додавання `AbortController` на екрані
зʼявилось `Error: signal is aborted without reason` — `StrictMode` розмонтував компонент,
очищення викликало `abort()`, `fetch` упав, `catch` виставив `status: "error"`.
→ Фільтруємо. Обрали `if (controller.signal.aborted) return` замість
`error.name === "AbortError"`: перевіряємо **факт скасування**, а не тип помилки — так
покриваються і падіння, що прилетіли не з `fetch` (наприклад з `response.json()`).

**`304 Not Modified` у Network ≠ статус у коді.** Браузер обробляє 304 сам: бере тіло зі свого
кешу і віддає коду відповідь зі `status === 200`. `response.status` ніколи не буде 304.
DevTools показує реальний мережевий обмін, `fetch` — уже розгорнуту відповідь. Це два різні шари.
Побачити чисті 200 — галочка **Disable cache** у Network.

**`response.ok` надійніше за `status === 200`.** `ok` — це діапазон 200–299, тому пропустить
201 (Created) і 204 (No Content). Жорстке порівняння зламало б легальний POST-кейс.
Порівнювати конкретне число варто лише коли воно щось означає для логіки (`404` → «не існує»).

**`discountPercentage` — це процент, не ціна.** Кінцеву ціну рахуємо самі, і формула потрібна
в трьох місцях (картка, сторінка товару, сума кошика) → окрема функція в `lib/`.
Рахунок і форматування розділені: кошику потрібне **число** для додавання, а не рядок `"$13.51"`.
Округлення до копійок обовʼязкове — інакше `760.6549999999999` через плаваючу точку.

### Дрібне, але корисне

- `import { useEffect, type ReactNode } from "react"` — inline type import, один рядок замість двох
- `void loadProducts()` — офіційно задокументований спосіб заглушити
  `@typescript-eslint/no-floating-promises`, але він **не обробляє** проміс, а лише позначає намір.
  Після додавання `try/catch` усередині стає не потрібен
- `key={product.id}`, не індекс масиву — на Кроці 5 при пагінації елементи підмінятимуться
  на тих самих позиціях
- `object-contain`, не `cover` — товари DummyJSON з різними пропорціями і часто на прозорому фоні
- `fix:` у Conventional Commits означає баг **у поведінці програми**; правка тексту
  в коментарі — це `docs:` або `chore:`

## Відкриті питання

- **ADR-007** — фільтр по ціні: сервер чи клієнт. Вирішуємо на Кроці 4, дописуємо в ADR самі.
- **ESLint** — додати `eslint-plugin-react` (ловив би `return AppRouter`) і `import/order`
  (сортування імпортів замість ручних коментарів-груп). Зробити, коли зʼявиться кодова база.
- **Скоуп vs API** — свотчі кольорів і чіпи розмірів з референсу нічим наповнити: у DummyJSON
  таких полів немає. На їх позиції — рейтинг і наявність.
